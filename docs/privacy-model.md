# Privacy model

Each tool displays a privacy mode. On-device tools do not send their inputs to the API. The optional clock synchronization request returns only `unixMs` and never receives a secret, URI, token, file or password. Network diagnostics contact the configured API only after the user starts a check and send the target or action needed for that check. Feedback forms submit only after the user chooses Send. Password generation and strength analysis run in browser memory; the EFF passphrase wordlist and zxcvbn analyzer are loaded as local application assets only. Favorites, recent tools, language and theme contain tool IDs and preferences only.

QR generation, QR image decoding, Base64 conversion, text hashing and file checksums remain inside browser memory. QR images are decoded from upload, paste, drag/drop or an explicitly granted camera stream; the reader shows decoded text before any optional HTTP/HTTPS navigation. Base64 file work is bounded at 10 MiB and File Checksum is bounded at 200 MiB, with cancellable workers that process chunks rather than uploading or persisting files. Input values, decoded values, file metadata, filenames and digests are not put in URLs, cookies, local preferences, logs or analytics. A download is created only after the user requests it.

JWT tokens, JSON text, UUID batches, timestamp values and selected time zones follow the same memory-only rule. JSON workers have no network capability and worker messages are neither logged nor persisted. The network suite uses its separate, user-initiated request path.
